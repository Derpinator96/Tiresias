- 2026-10-03: fail closed (strip.py raises Unparsed, nothing is sent) when: the SQL does not parse; a table is not a QuickMart table (this also drops catalog queries); a column is ambiguous or unknown; any identifier other than a code survives (this closes the uppercase-identifier gap noted in contracts/NOTES.md); the output does not match the contract's hashed_sql pattern. - 2026-10-03: plan conditions (Filter, Index Cond, Recheck Cond, Join Filter, Hash Cond, Merge Cond) are hashed one by one. One that fails is dropped and the node is marked `filter_redacted`.
- 2026-10-03: template codes are HMAC of pg_stat_statements' normalized text, not of queryid: queryid depends on table OIDs and changes on every reseed. Plans join templates through jsonlog `query_id` = pg_stat_statements `queryid`.
- 2026-10-03: only queries of `workload.app_role` (quickmart_app) are ingested, so test and catalog queries never become templates. db/seed.py creates the role.
- 2026-10-03: self time per plan node = total minus children. For nodes under Gather, or Parallel Aware nodes, per-loop time is used as wall time (workers overlap); otherwise time is multiplied by loops. Negative results clamp to 0.
- 2026-10-03: rounding to 2 significant figures applies to row counts, distinct counts, est_rows, est_cost, table rows and sizes. Times (mean_ms, total_ms, self_ms) are not counts or sizes and are rounded to 0.1 ms or 0.001 ms only.
- 2026-10-03: `TableMeta.writes_per_s` is measured (row writes since the stats reset, per second), but there is no steady write workload yet, so after `make seed` it mostly reflects the seed's bulk COPY. pgbench is pending.

- 2026-10-03: `POST /v1/approve` is built (supersedes the MISSING line above), in `gateway/approve.py`. It takes the whole Config, not the doc's `config_id`: the gateway keeps no config store, and the dashboard already holds the Config. - 2026-10-03: migration.sql: `CREATE INDEX CONCURRENTLY "bt_<table>_<cols>"` per add_index (no IF NOT EXISTS, so a name clash fails instead of later letting rollback drop an index the migration did not make); `DROP INDEX CONCURRENTLY` per drop_index; rewrites as a commented suggested code change with the latest logged query and its rewrite; partition as commented manual steps with placeholders. rollback.sql undoes the actions last first: `DROP INDEX CONCURRENTLY IF EXISTS` (also clears an invalid index a failed CONCURRENTLY build leaves), and `pg_get_indexdef` from pg-prod, made CONCURRENTLY, to recreate a dropped index. Dropping an index that a constraint owns (primary keys) is refused with 400.
- 2026-10-03: post_deploy_check.py is `gateway/post_deploy_check.py` with its `PARAMS` line filled in: the latest logged query of every slow template that reads a table an index action touches (real values), `approve.post_deploy_check_minutes`, `approve.rollback_if_median_worse_by` and `sandbox.warmup_runs`. Two phases: `baseline` before migration.sql saves medians next to the script; `check` after it replays for the same time and runs rollback.sql if any template's median is more than the threshold worse. Connection from `BT_DSN` or the PG* variables, never from argv. Templates without a logged query are not replayed. Rewrites are not replayed: rollback.sql cannot undo a code change.

- 2026-10-03: step 25, drift windows (gateway/windows.py). A daemon thread started with the gateway samples pg_stat_statements every `miner.drift_sample_s` (2 s): raw cumulative calls and total time per template code, the same app-role templates as /v1/templates/slow (Template now keeps the raw, unrounded totals privately).
