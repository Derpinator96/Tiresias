Blind Tuner recommends PostgreSQL indexes while its AI sees only hashed metadata

A gateway inside the database owner's network replaces every table and column name with a keyed hash and strips every value before anything reaches the AI. The AI proposes an index from that metadata. The proposal is measured on a synthetic copy of the database before a DBA sees it.

The fix depends on the shape of a query, not on its rows

A typical slow dashboard query filters one column with = and a date column with >=. With no index on those columns, PostgreSQL reads every row of the table to keep a small fraction. A composite index on the two columns, equality column first, lets it read only the rows it keeps.

Which column is compared with =, which with >=, how many rows exist and how many were read: all of that survives hashing, and it is what the index decision needs. The names and the values do not survive.

What crosses the boundary and what does not

CategoryExampleSent to the AI?
Valuescustomer emails, amounts, dates, filter valuesNo. Replaced by ?; every payload is scanned for planted canary values before it leaves.
Namestable and column namesNo. HMAC-SHA256 codes such as t_7a3f91c2 (illustrative), computed with a key that stays in the gateway.
Statistics value listsmost common values, histogram bounds from pg_statsNo. Replaced by one skew score from 0 to 1.
The DBA's question"why is this dashboard slow?"No. Mapped to query template codes inside the gateway.
Query shapewhich column uses =, joins, groupingYes. The fix depends on it.
Sizesrow counts, table and index sizesYes, rounded to 2 significant figures.
Column rolesdate, number, identifierYes, as role tags.

The shape of the schema (how many tables, how they link) still reaches the AI and can hint at the kind of business. Blind Tuner claims that no raw value or real name crosses the boundary, not that nothing does.

How the privacy claim is checked

  • Twenty canary placements (fake emails, names, phone numbers, amounts, product names, query comments, filter values and one question) are planted in the demo database and workload. Every payload bound for the AI is scanned for them, exactly and by 6-character fragment, and blocked on a hit.
  • A negative control scans the same logs with hashing and stripping switched off. It finds the canaries, which shows that the scanner works and that a zero means something.
  • A ledger records the size and SHA-256 of every payload that left.
  • The AI's container is on a Docker network with no route to either database; a test proves that a connection attempt fails.
