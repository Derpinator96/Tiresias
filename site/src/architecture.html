Two networks, one gateway between them

Everything that touches raw data runs on a private network. The AI components run on a second network that reaches only the gateway. The gateway is the one component on both, and it lets through hashed metadata only.

Request flow for one slow query

  1. PostgreSQL logs the slow query's shape in pg_stat_statements and its executed plan through auto_explain.
  2. The gateway parses both with sqlglot, replaces names with codes, replaces values with ?, and drops comments. Anything it cannot parse is withheld, not sent.
  3. The miner runs FP-Growth over the hashed workload, weighted by time, and proposes composite index candidates in column order.
  4. The search scores candidates with HypoPG, which plans each query as if the index existed without building it, and a cost model that turns the plan into milliseconds.
  5. The gateway builds the chosen index on the statistical twin and measures the query before and after, then checks that the result rows are unchanged.
  6. The LLM agent calls these steps as tools and explains the result in hashed names. A checker blocks any answer containing a number that is not in a tool result.
  7. The gateway translates the codes back to real names for the DBA, on the private side only.

The AI cannot reach the database, by construction

The services run under Docker Compose. Both databases sit only on an internal network. The AI container sits on a second internal network shared with the gateway, plus one outbound network for the LLM API. An automated test inside the AI container tries to connect to both databases, by name and by IP address, and passes only when every attempt fails.

What this build simplifies

ComponentIn this build
Cost modelPostgreSQL's own cost estimates, converted to milliseconds with a ratio measured from the slow query's real run. The planned graph neural network is not built.
Index searchGreedy: add the best candidate until nothing improves. The planned reinforcement learning agent is not built.
Statistical twinEach column generated on its own from the production statistics. Correlations between columns are not preserved yet.
VerificationResult checksums on the twin. SQL equivalence checking is not built.
Write costNot measured. Search uses an assumed penalty per index.
AI network egressOpen internet access for the LLM call. Restricting it to the LLM host is not built.
ScopeOne hero query on a 1,000,000-row demo table. Join, partitioning and workload-drift queries are not built.
